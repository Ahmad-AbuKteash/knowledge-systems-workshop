Nimbus API key lifecycle and rotation

Version: 2026.2. Effective date: 2026-09-01. Owner: Developer Platform and Security.

Access scope: workshop-public. Supersedes previous-policy.md.

Applicability

Customer-managed Nimbus API keys; workforce login follows source-12 and webhook secrets follow source-29.

Creation and scope

Only an authorized workspace administrator may create an API key. Choose the minimum operation scopes and record a human owner, application purpose, and expiry. Production keys expire after at most 90 calendar days. Sandbox keys expire after at most 30 calendar days.

Planned rotation

Create a replacement with the same necessary scopes, deploy it through the approved secret store, verify successful requests, and revoke the old key. Planned overlap may last at most 24 hours. Never paste a full key into support tickets or source control; use its key ID for investigation.

Compromise

Suspected exposure requires immediate reporting under source-22 and prompt revocation under Security coordination. The normal 24-hour overlap is not a guaranteed grace period after compromise. Revocation blocks future requests but does not undo past operations.

Quotas and boundaries

Nimbus operation quotas apply per key under source-05; creating additional keys to evade plan limits is prohibited. A rotated key's first request can still fail for missing scope or wrong environment. This procedure contains no usable keys and does not define account-wide commercial limits.
