# Key rotation handover card

Record version: 1.0. Owner: Developer Platform and Security. Access scope: workshop-public.
Record type: checklist.

Published: 2026-10-17. Effective: 2026-10-17 onward.
For a Nimbus planned rotation, record old key ID, replacement key ID, owner, environment, required scopes, deployment timestamp, verification evidence, and revocation timestamp. Verification must include the application path that actually uses the key; a manual test from a different host is insufficient by itself. If deployment fails, record whether the old key remains active and the approved next action. Do not extend overlap beyond 24 hours without a separately approved Security exception. Keep secret values out of the handover.
