Nimbus release gates and emergency changes

Version: 2026.2. Effective date: 2026-09-01. Owner: Release Engineering.

Access scope: workshop-public. Supersedes previous-policy.md.

Applicability

Nimbus production application releases; database migrations have additional gates in source-28.

Standard release

Every production release needs a tracked change, passing automated checks, review by an engineer other than the author, and a rollback or roll-forward plan. The service owner approves the release window. Deploy from a versioned artifact; rebuilding an unrecorded local working tree is not permitted.

Rollout

Start with a 10% canary for at least 15 minutes. Continue only if the change's declared error and latency checks pass. The default abort threshold is a five-minute error rate above 2% or p95 latency above twice the previous 30-minute baseline. Record the actual baseline and observed metrics.

Emergency route

For an active SEV1, the incident commander may shorten the canary after an independent review and service-owner approval. Document why and review the change by the next business day. Emergency status does not waive artifact tracking or access controls.

Completion

Attach deployment timestamps, artifact ID, gate results, and outcome to the change. A green build is necessary but does not prove production recovery. This policy does not define service-specific SLOs; see source-25.
