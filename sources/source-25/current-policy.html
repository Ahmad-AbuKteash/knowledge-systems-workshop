Nimbus service objectives and error budgets

Version: 2026.2. Effective date: 2026-09-01. Owner: Site Reliability Engineering.

Access scope: workshop-public. Supersedes previous-policy.md.

Applicability

Nimbus Core order-read API availability; Managed Services exports have separate objectives not specified here.

Objective and measurement

The order-read API has a 99.9% monthly successful-request objective. Eligible requests are production GET /v2/orders requests reaching the Nimbus edge. Successful requests are HTTP 2xx and 3xx. Exclude client-caused 4xx; count server-caused 429 and 5xx as failures. Planned maintenance is included.

Budget calculation

Allowed failed requests = eligible requests x 0.001. Consumed budget = failed requests / allowed failed requests. Preserve raw counts and round only displayed percentages. With zero eligible requests, report the budget as undefined rather than claiming perfect availability.

Operational action

If more than 75% of the monthly budget is consumed, the service owner reviews planned feature releases with SRE. At 100%, pause non-reliability releases unless the engineering director grants a documented exception. A single alert does not itself change the measured budget.

Contract boundary

This internal objective is not a customer service-level agreement or automatic refund promise. Contractual credits require their own agreement and source-26. Source-05 defines API quotas; quota entitlement and availability measurement answer different questions.
